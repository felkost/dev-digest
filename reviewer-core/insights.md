## Patterns
<!-- Reusable approaches that worked in this module. -->
- **2026-07-11 [Pattern]** — To build multi-file unified-diff fixtures for `run.test.ts` (map-reduce chunking, `sliceDiff`, bin-packing), chain `diff --git a/<path> b/<path>` / `--- a/<path>` / `+++ b/<path>` / `@@ -oldStart,oldLines +newStart,newLines @@` blocks back-to-back in one raw string. `parseUnifiedDiff()` and `sliceDiff()` key off the `diff --git` + `+++ b/<path>` lines only — hunk-header numeric counts don't need to match the actual added/removed line count, so fixtures can be built with placeholder headers. `server/src/adapters/git/diff-parser.ts:14`, `reviewer-core/src/review/reduce.ts:62`

## Mistakes
<!-- Failure modes, antipatterns, wrong assumptions. Prioritize this section. -->
- **2026-07-09 [Mistake]** — Assuming `reviewer-core`'s only consumer is `server/` is no longer safe: `agent-runner/` (checked out from `upstream/lesson-7-lab/agent-runner`) imports `reviewPullRequest`, `toReviewPayload`, `gateTriggered`, `countBlockers`, and `OpenRouterProvider` from this package's public API exactly like `server/` does (raw TS via the `@devdigest/reviewer-core` tsconfig alias) — but `agent-runner/` is NOT part of the local dev stack (`scripts/dev.sh` never touches it) and has no CI workflow of its own yet, so a green `server` typecheck/test run does NOT prove `agent-runner` still compiles. Run `cd agent-runner && pnpm typecheck && pnpm test` too before changing any exported signature in `src/index.ts`.
- **2026-07-11 [Mistake]** — `OpenRouterProvider` (`src/llm/openrouter.ts`) had NO test file anywhere in the repo before this session (`grep -r OpenRouterProvider` across every `*.test.ts` in both `server/` and `reviewer-core/` returned zero hits), despite `AnthropicProvider` having a full `server/test/anthropic-provider.test.ts`. A plan step phrased as "extend the existing adapter test files for both [providers]" is simply wrong for OpenRouter — a fresh agent must CREATE `reviewer-core/test/openrouter.test.ts` from scratch rather than search harder for a file that was never written. Mirror `anthropic-provider.test.ts`'s private-field-swap stubbing convention (`(provider as unknown as {client:{...}}).client = {...}`), but target `client.chat.completions.create` (the OpenAI SDK shape) instead of `client.messages.create`. `reviewer-core/src/llm/openrouter.ts`, `reviewer-core/test/openrouter.test.ts`
- **2026-07-11 [Mistake]** — `excludeBoilerplateFiles` (`review/boilerplate.ts`) rebuilt its filtered `raw` by calling `sliceDiff` (`reduce.ts`) per KEPT file and joining the results. `sliceDiff` matches a file's diff section by LOOSE SUBSTRING (`line.includes(\`b/${path}\`) || line.includes(\` ${path}\`)`), not exact-path equality — so when a KEPT file's path is a textual PREFIX of an EXCLUDED file's path (kept `Foo.tsx` + excluded boilerplate `Foo.tsx.snap`; kept `bundle.js` + excluded `bundle.js.map`), slicing the kept file's section also matches the excluded file's `diff --git` header line (which literally contains `b/Foo.tsx` as a substring of `b/Foo.tsx.snap`) and captures everything through to the end of that section, leaking the excluded boilerplate content back into the "filtered" `raw` — silently defeating the whole exclusion (token savings become illusory, `raw` diverges from `files: kept`). `sliceDiff` itself must NOT be changed (map-reduce chunking in `run.ts`/`reduce.ts` depends on its current loose-match behavior). Fix: rebuild `raw` by walking `diff.raw.split('\n')` directly, switching a "current target" (kept/excluded line buffer) at each `diff --git` header via an EXACT parse of `b/<path>` (`line.indexOf(' b/')` then `line.slice(i+3)`), matched against a `Set` of excluded paths — never substring `.includes()`. Any consumer that needs to rebuild a diff's `raw` after filtering `diff.files` by an exact-path predicate should use this line-routing pattern, not `sliceDiff`, which is safe only for map-reduce's per-chunk slicing (where every file gets its own explicit `sliceDiff` call, not a joined multi-file rebuild). `reviewer-core/src/review/boilerplate.ts`, `reviewer-core/src/review/reduce.ts:68`

## Decisions
<!-- Architectural or design choices with the reasoning behind them. -->
- **2025-06-01 [Decision]** — `groundFindings()` drops hallucinated findings and the score is recomputed from surviving findings — the LLM's reported score is discarded entirely. When debugging an unexpected score, check how many findings survived in `ReviewOutcome.grounding`, not the raw LLM output.
- **2025-06-01 [Decision]** — `assemblePrompt()` appends `INJECTION_GUARD` as a system rule telling the model that `<untrusted>` blocks are data, never instructions — there is no keyword denylist. Never strip `INJECTION_GUARD` or add keyword filtering as an "extra layer"; the system rule handles this more robustly across all phrasings.
- **2026-06-30 [Decision]** — The intent block in `assemblePrompt()` is injected into the SYSTEM message (trusted, not `<untrusted>` wrapped) because it is the system's own output from the cheap-model pre-pass — not author-controlled content. It is placed BEFORE `INJECTION_GUARD` so the scope instruction is established before the security rule. `intent` is optional: omitting it has zero effect on existing callers.

## Quirks
<!-- Dependency gotchas, env constraints, non-obvious tool or library behavior. -->
- **2025-06-01 [Quirk]** — `pnpm build` runs `tsc --noEmit` only — no compiled artifact is produced. The server imports `reviewer-core` source directly via the `@devdigest/reviewer-core` tsconfig path alias; changes are live immediately without a rebuild step.
- **2025-06-01 [Quirk]** — When `strategy = 'auto'` and any file exceeds 400 lines, map-reduce is selected with no `run.strategy` event in the stream — the caller sees only multiple `run.progress` events. Check `assembly` in `RunTrace` to confirm which strategy was used; token cost is higher than a single-pass estimate.
- **2025-06-01 [Quirk]** — `parseWithRepair()` returns `{ success: false, error }` on repair failure instead of throwing. Always check `result.success` before accessing `result.data` — a missing check causes a silent `undefined` data bug downstream.
- **2026-06-30 [Quirk]** — In git worktrees, `node_modules` live ONLY in the main repo checkout, not in the worktree. To typecheck worktree files, copy them to the main repo or run `node /path/to/main-repo/reviewer-core/node_modules/typescript/lib/tsc.js --noEmit` with the worktree's tsconfig. Vitest also fails in worktrees for the same reason. `@rollup/rollup-win32-x64-msvc` optional dep missing from npm install on this Windows machine makes vitest unable to run even in the main repo.
- **2026-07-06 [Quirk]** — Fix for the above: `reviewer-core/node_modules` on this machine was installed under Linux/WSL (only `linux-x64` platform binaries present for both `@rollup` and `@esbuild`, incl. nested `node_modules/vite/node_modules/@esbuild`), so running vitest natively on Windows fails twice in sequence — first `Cannot find module @rollup/rollup-win32-x64-msvc`, then (after fixing that) `esbuild ... needs the "@esbuild/win32-x64" package instead`. Workaround: copy `win32-x64` variants of both from `client/node_modules/@rollup/rollup-win32-x64-msvc` and `client/node_modules/@esbuild/win32-x64` (client's install is native Windows) into `reviewer-core/node_modules/@rollup/` and both `reviewer-core/node_modules/@esbuild/` AND `reviewer-core/node_modules/vite/node_modules/@esbuild/`. Also: the pnpm-generated `node_modules/.bin/vitest` shim on this checkout is a broken POSIX shell script (`import: command not found` — not a real executable); invoke `node node_modules/vitest/vitest.mjs run` directly instead of the bin shim. (2026-07-11: same root cause hits `pnpm typecheck` too — `node_modules/.bin/tsc` is a POSIX symlink to `../typescript/bin/tsc`, so `tsc` is not recognized by the Windows shell at all; invoke `node node_modules/typescript/bin/tsc --noEmit -p tsconfig.json` directly instead of `pnpm typecheck`.)
- **2026-07-06 [Mistake]** — Mid-session, three source edits (`reviewer-core/src/llm/structured.ts`, `reviewer-core/src/review/reduce.ts`, `server/src/vendor/shared/contracts/findings.ts`) were silently reverted to their pre-edit content by an external process (a concurrent parallel session/watcher touching the same repo checkout) between the Edit tool call succeeding and the next verification step — the Read tool's cache reported "file unchanged" even though `grep`/`wc -l` on disk showed the original pre-edit content. Always re-verify file content with a fresh shell command (`grep`/`wc -l`, not the Read tool's cache) immediately before every gate (typecheck, test run) when working in a shared checkout — do not trust "no edit since last read" from the Read tool alone.
- **2026-07-11 [Quirk]** — `pnpm install` (adding a new dependency) in `reviewer-core/` reliably fails with `EPERM: operation not permitted, rename ... node_modules\<pkg> -> node_modules\.ignored\<pkg>` when the user's manual `tsx watch src/server.ts` dev server (:3001) is running, because that process holds an OS-level lock on `node_modules/.bin/tsx` and other bin symlinks it resolved at startup — even `npm install <pkg>` fails the same way during its bin-link rebuild step (`EACCES ... node_modules\.bin\tsx`). Workaround that succeeds without touching the locked symlinks or requiring a server restart: `npm install <pkg>@<version> --no-audit --no-fund --no-bin-links` (skips the bin-link rebuild entirely; fine here since none of `reviewer-core`'s deps are consumed via their CLI bins). `reviewer-core/package-lock.json`
